Microsoft Agent 365现已正式发布，扩展代理安全与治理能力

AI代理已经存在于您的环境中。它们出现在您期望的地方（如Microsoft Copilot、Microsoft Teams和Microsoft 365），随着技术发展甚至出现在更多地方（本地自主个人AI助手或连接到您敏感数据的新型SaaS代理）。

问题不在于代理是否存在，而在于它们 proliferation速度快、跨越应用程序、端点和云端，通常在 accountable for risk的团队的可见性和控制范围之外运行。当代理可以调用工具、访问数据并与其他代理交互时，任何"有用"的工作流都可能在几秒钟内转变为数据过度共享、工具滥用或过度特权操作。随着代理变得越来越容易创建和部署，您的攻击面也随之增长。

这就是为什么端到端可观测性很重要：您无法管理您看不到的东西，您也无法保护您不理解的东西——尤其是当代理数量是一个移动目标时。

Microsoft Agent 365帮助您控制代理蔓延，作为您的控制平面，用于观察、治理和保护代理及其交互——包括使用Microsoft AI构建的代理和来自我们生态系统合作伙伴的代理——使用您的团队已经运行的管理和安全工作流。

发现和管理本地和云托管的代理

用户正在他们的设备上安装代理（如OpenClaw和Claude Code），并采用由开发者在新的和新兴平台上构建的SaaS代理。许多这些本地和云托管的代理在传统治理之外不受管理地运行，因为它们自主执行任务、修改代码或访问机密信息，创建了新一波的影子AI。

为了帮助组织应对加速的代理蔓延和不受管理的代理的兴起，我们作为Agent 365、Microsoft Defender和Intune的一部分引入新功能，以便您可以发现影子代理并应用适当的控制，例如阻止不受管理的代理。

发现和管理本地代理

通过Microsoft Defender和Intune，组织将能够发现和管理在Windows设备上运行的本地AI代理，首先是OpenClaw代理，并很快扩展到其他广泛使用的代理，如GitHub Copilot CLI和Claude Code。在前沿计划中注册的客户提供可以看到组织中是否使用了OpenClaw代理、这些代理在哪些设备上运行，并使用Intune策略阻止OpenClaw在这些设备上运行的常见方法。

在Microsoft 365管理中心，新的影子AI页面中的OpenClaw；以及在Intune管理中心。客户可以持续检测托管设备并阻止OpenClaw在这些设备上运行的常见方法。

通过Agent 365注册表，本地代理的清单将在Defender和Intune中可用，这样IT、端点管理和安全团队可以在其环境中获得一致的已发现本地代理视图，并采取适当的行动。

从2026年6月开始，Microsoft Defender还将为每个代理提供资产上下文映射，包括它们运行的设备、为这些代理配置的MCP服务器、与之关联的身份，以及这些身份可以访问的云资源。这将为安全团队提供评估曝光和潜在爆炸半径所需的上下文。他们可以使用熟悉的端点数据调查代理活动，例如文件访问和网络行为，并使用这些洞察来识别配置错误甚至定义自定义检测。

超越监控，组织将能够应用基于策略的控制来为代理可以做什么设置护栏——帮助保护代理和组织免受妥协和滥用——初始支持通过Intune为OpenClaw提供。如果托管代理表现出恶意行为模式，例如试图访问或泄露敏感数据，Defender将能够在运行时阻止编码代理，并生成带有丰富事件上下文的警报以支持调查和响应。

上下文映射功能、基于策略的控制加上运行时阻止和警报将于2026年6月在Agent 365中通过Intune和Defender公开预览提供。

使用网络控制保护代理免受互联网威胁

AI代理可以比人类用户快得多地操作。没有适当的护栏，它们可以连接到危险的web目的地、与未批准的AI服务交互、不安全地处理敏感文件，或通过恶意基于提示的攻击被操纵。当安全团队缺乏对代理流量到互联网、SaaS和AI服务的一致可见性和控制时，这些风险更难管理。

为了让安全团队在网络层拥有一致的方式来检查代理流量，今天在正式可用时，Agent 365扩展Microsoft Entra网络控制到Microsoft Copilot Studio代理和在用户端点设备上运行的代理，包括OpenClaw等本地代理。这些控制可以帮助识别未批准的AI使用，仅限制到批准web目的地的连接、过滤危险的文件移动，并帮助在导致有害操作之前阻止恶意基于提示的攻击。
