Lens Agents：跨云和桌面的 AI Agent 统一治理平台

📰 Help Net Security  |  📅 2026年5月4日

发生了什么

Lens by Mirantis 宣布推出 Lens Agents，这是一个治理驱动的平台，用于跨企业系统运行 AI Agent。平台支持在桌面和云环境中统一管理、治理和保护任何 AI Agent。

核心价值主张："AI Agent 已在每个企业内运作，问题是它们是否受到治理。云平台只能管理在它们云上运行的内容，而今天大多数 AI 使用发生在拥有跨多云访问权限的笔记本电脑上。这些都没有得到适当的治理。"

Lens Agents 使企业能够连接任何 AI Agent（包括 Claude、Cursor、Copilot 等桌面工具；任何框架构建的外部自主 Agent；以及直接在 Lens Agents 上创建的平台 Agent），并通过完整的企业治理、审计和策略控制将其接入企业系统。

核心能力

1. Agent 身份与访问控制 每个 Agent 使用独立身份，受企业策略管理。这意味着即使 Agent 运行在用户本地设备上，IT 也能对其行为进行治理。

2. 沙箱隔离 隔离的执行环境防止 Agent 的意外操作或横向移动。如果 Agent 试图访问未授权资源，沙箱会自动阻止。

3. 服务端凭证注入 凭证永不暴露给 Agent。系统通过安全隧道注入凭证，Agent 可以在不知道密码的情况下访问授权资源。

4. 完整审计日志 跨所有 Agent 交互和系统的全面日志记录。满足合规审计需求，支持 SOC 2 和 EU AI Act 要求。

5. 基于策略的治理 集中式规则定义 Agent 的访问权限、行为范围和自主级别。企业可以根据 Agent 类型、用户角色或数据敏感性设置不同策略。

6. 主动成本控制 实时执行使用和支出限制。当 Agent 预算用尽时，系统会自动停止 Agent 运行，防止意外超支。

合规支持

  • SOC 2 Type 1
  • ISO 27001
  • EU AI Act：支持受控自主级别定义，满足法案对高风险 AI 系统的要求

为什么重要

Lens Agents 解决了企业 AI 治理的"最后一英里"问题：大多数 Agent 运行在用户的本地设备上（Claude Code、Cursor 等），而传统的云安全工具对此毫无办法。

Lens 此前是 Kubernetes IDE，在全球拥有超过 100 万开发者用户。Lens MCP Server 于上月发布，使 AI 助手能够连接 Kubernetes 环境。Lens Agents 则将这一能力扩展为完整的企业 AI 运营平台。

技术架构

Lens Agents 的架构基于：

  • 安全隧道：隔离 Agent 与敏感资源的直接连接
  • 凭证管理：集中的凭证存储和按需注入
  • 策略引擎：基于 OPA（Open Policy Agent）的策略执行
  • 日志收集：集中式日志，兼容 SIEM 系统

企业采用路径

  1. 注册 Lens Agents 早期访问
  2. 连接现有 Agent（Claude、Cursor、Copilot 等）
  3. 配置治理策略（权限、数据访问、成本限制）
  4. 启用监控和审计
  5. 定期评估 Agent 行为
