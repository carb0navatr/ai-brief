DeepSeek V4：百万 token 上下文如何真正改变 AI Agent 的记忆边界

📰 Hugging Face Blog  |  📅 2026 年 4 月 24 日

摘要

DeepSeek 发布 V4 版本，提供两个 MoE 检查点：DeepSeek-V4-Pro（总参 1.6T，活参 490B）和 DeepSeek-V4-Flash（总参 284B，活参 13B）。两者均支持 100 万 token 上下文窗口，并专为 Agent 工作负载设计了 DSec 沙箱和 |DSML| 工具调用专用 Token Schema。在 SWE Verified、MCPAtlas 等 Agent 基准测试中与前沿闭源模型持平。

核心创新

1. 100 万 token 上下文：Agent 的记忆革命

长上下文对 Agent 工作负载意义重大：

场景 传统 32K 模型 DeepSeek V4 1M Token
消化完整代码库 分批处理，跨文件记忆断裂 一次性全量输入，跨文件语义连贯
长篇文档分析 需分层摘要，丢失细节 全量保留，精细定位
视频帧分析 只能处理少量帧 可同时分析数千帧关键信息
Agent 多轮对话 历史上下文快速超出限制 可维持数百轮完整上下文

2. 混合注意力机制：CSA + HCA

DeepSeek V4 采用混合注意力架构：

  • CSA（Cross-Block Sparse Attention）：跨块稀疏注意力，处理长距离依赖关系
  • HCA（Hybrid Chunk Attention）：混合分块注意力，优化局部精细任务

两者结合使 1M token 上下文在推理效率上可行，而非简单地将 KV cache 线性放大。

3. DSec：专为 RL 训练设计的沙箱

DSec（DeepSeek Execution Container） 是一个 Agent RL 训练的沙箱环境，解决的核心问题：

  • Agent 在训练中执行代码、调用工具时需要隔离环境
  • DSec 提供可重现、可计量的执行环境
  • 支持大规模 RL rollouts，显著提升 Agent 后训练效率

4. |DSML| Token Schema：工具调用的专用语法

DeepSeek V4 引入了 |DSML|（DeepSeek Markup Language）Schema，为 Agent 工具调用设计：

|DSML| think: [思考过程] |DSML|
|DSML| action: [工具名称] |DSML|
|DSML| result: [工具输出] |DSML|

关键特性：

  • Interleaved Thinking：模型可以在工具调用之间进行显式推理，而非简单线性输出
  • 专用 Token：工具调用的触发和解析完全通过专用 Token 隔离，避免解析歧义
  • Think Modes：支持三种推理模式——Non-think（快速响应）、Think High（显式推理）、Think Max（最大推理深度，需至少 384K 上下文）

5. Agent 基准测试表现

SWE Verified 持平 SOTA
MCPAtlas 持平 SOTA
内部 R&D 基准 持平 SOTA

核心问题：工具生态适配。主流框架（LangChain、LlamaIndex、CrewAI 等）是否会在近期支持 |DSML| Schema，将决定这一创新的实际影响力。

可用模型

四个检查点均已在 Hugging Face Hub 发布：

  • deepseek-ai/DeepSeek-V4-Pro（1.6T/49B 活参，instruct）
  • deepseek-ai/DeepSeek-V4-Flash（284B/13B 活参，instruct）
  • deepseek-ai/DeepSeek-V4-Pro-Base（base 版本）
  • deepseek-ai/DeepSeek-V4-Flash-Base（base 版本）

Instruct 模型支持三种推理模式，推荐采样参数：temperature=1.0, top_p=1.0。Think Max 模式需要至少 384K token 上下文窗口。

对 Agent 开发者的影响

DeepSeek V4 的出现意味着：

  1. 长程 Agent 任务终于有了经济上可行的模型选择
  2. |DSML| Schema若被主流框架采纳，将成为 Agent 间工具调用的新标准
  3. 13B 活参的 Flash 版本降低了本地部署的门槛，Jetson 和消费级 GPU 也能运行
