Anthropic 复盘 Claude Code 三次质量回退：从"自己的 evals 没catch到"学什么

 |  📅 2026年5月初

原文链接: InfoWorld | Anthropic Postmortem

信源: InfoWorld（技术媒体）

摘要

Anthropic 发布了一份罕见的公开复盘报告，坦诚承认 Claude Code 在六周内发生了三次质量回退——而其内部评估都未能发现。问题包括：默认推理强度调整引入的 bug、缓存逻辑错误、以及 prompt 措辞调整导致的 3% 编码质量下降。

为什么重要

Anthropic 被业界公认为"最重视 evals 的 AI 公司"，连他们都在评估上翻车，这说明：AI 智能体质量保证是极其困难的工程问题，即使是顶级团队也无法幸免。

三次回退详情

时间 问题 原因 后果
3月4日 推理强度调整 将默认从"高"改为"中"（evals 显示"略低智能但显著降低延迟"） 用户感知到质量下降
3月26日 缓存 bug 空闲一小时后应清除 thinking，但代码错误导致每次对话都清除 性能异常
4月16日 prompt 措辞变更 "更简洁"的指示导致 3% 编码质量下降（仅在更大规模 ablation 中发现） 长期性能劣化

关键教训

评估的局限性：

  1. 标准 benchmark 无法覆盖全部场景：Claude Code 的标准发布门禁没有包含更大规模的 ablation suite
  2. 用户反馈是最真实的信号：Anthropic 用户几乎在问题上线后立即报告了问题
  3. 改变越小，风险越隐蔽：两行看似无害的 prompt 调整导致 3% 质量下降

改进建议

文章提出了几点工程实践建议：

  1. 建立更诚实的数据闭环：不仅看内部指标，也系统性地收集用户反馈
  2. 发布门禁中加入 regression test：如果分数下降，不发布
  3. 先写 eval，再写 prompt：明确"好"的标准在优化之前

行业影响

这份复盘对于所有开发 AI 智能体应用的团队都有参考价值。它提醒我们：AI 系统的质量保证需要比传统软件更严格的工程实践，包括：

  • 更全面的自动化测试
  • 更快的用户反馈收集机制
  • 对"小改动"的敬畏之心
