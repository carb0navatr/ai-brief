深度 | 从提示词注入到 AI-BOM：Agentic AI 安全的系统性解读

原文链接: The Register | CSO Online

信源: The Register + CSO Online（技术媒体）

摘要

随着 Agentic AI（智能体 AI）的广泛部署，安全威胁正在从理论走向现实。本篇综合分析两大核心安全议题：AI 供应链的可见性问题（AI-BOM）和智能体运行的运行时安全问题（CISA advisory）。

为什么重要

AI 智能体与传统软件的根本区别在于：智能体具有动态决策能力，可以执行多步骤任务，可以访问多种工具和数据源。这使得传统软件安全模型失效。

AI-BOM：供应链的透明度缺失

问题根源： 当你向 AI 提问时，你知道它的答案来自哪里吗？企业版 AI 应用的情况更复杂：

  • 模型来自哪里？训练数据是什么？
  • 调用的外部 API 服务是否可信？
  • 智能体的 skills 是谁开发的？是否有恶意代码？
  • MCP 服务器连接到哪里？数据传输到哪里？

AI-BOM 的解决方案：

AI-BOM 清单（示例）
├── 模型: gpt-4o-2024-05-13
│   ├── 基础: GPT-4o
│   ├── 微调: 企业定制层
│   └── 量化: INT4 ONNX
├── 数据集
│   ├── RAG: 企业内部知识库
│   └── 实时: 网络搜索 API
├── SDK & 库
│   ├── LangChain: 0.2.x
│   ├── OpenClaw SDK: 1.4.x
│   └── MCP Client: 0.5.x
├── 工具 (Tools)
│   ├── Calendar: Google Calendar API
│   ├── Email: Microsoft Graph API
│   └── File: SharePoint Online
├── Skills
│   ├── code_analysis: v2.1 (自研)
│   └── report_generator: v1.3 (第三方)
└── 工作流配置
    ├── 最大工具调用次数: 50
    └── 敏感操作审批: 启用

CISA 红线：运行时安全的硬性要求

CISA 联合 advisory 将以下风险领域列为必须治理的硬性要求：

风险类型 描述 应对措施
提示词注入 恶意指令覆盖原任务 输入验证、输出过滤
数据泄露 敏感信息意外暴露 数据分类、访问控制
工具滥用 非预期系统操作 最小权限、审批机制
权限蠕变 权限随时间扩大 定期审计、自动回收

实施路径

Phase 1: 可见性（0-3个月）

  • 建立 AI 资产清单
  • 绘制智能体-工具-数据连接图
  • 评估第三方 skills 安全性

Phase 2: 控制（3-6个月）

  • 实施 AI-BOM 管理流程
  • 部署运行时监控
  • 建立人工审批工作流

Phase 3: 自动化（6-12个月）

  • 自动化安全策略执行
  • 异常检测和响应自动化
  • 持续合规监控

结论

AI 智能体安全不能依赖"事后打补丁"，需要在部署前就建立系统性框架。AI-BOM 解决的是"你知道有什么"，CISA 红线解决的是"你知道它在做什么"。两者结合才是完整的 Agentic AI 安全视图。
