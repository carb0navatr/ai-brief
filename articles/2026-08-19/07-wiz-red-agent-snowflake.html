Wiz Red Agent 发现 Snowflake GitHub Actions 注入漏洞：AI 辅助审查未能识别风险

📰 Wiz Research

Wiz Research 披露，其自主安全研究工具 Red Agent 在 Snowflake 的公开仓库中发现 GitHub Actions 工作流注入漏洞。Wiz 称，Snowflake 在 2026 年 6 月 23 日收到负责任披露后当天修复漏洞、轮换受影响凭据，并确认暴露窗口内只有 Wiz 的测试活动。

原文要点

  • 漏洞位于 snowflakedb/snowflake-connector-net 仓库的 jira_issue.yml：工作流由新建 Issue 触发，并将攻击者可控的 Issue 标题直接插入 run: 中的 shell 脚本。
  • Wiz 表示，任意未认证用户可通过精心构造的 Issue 标题在 GitHub Actions runner 中执行命令；相关 PR 于 6 月 18 日合并，漏洞在五天后被发现。
  • GitHub Advanced Security 扫描了包含漏洞工作流的最终 PR 版本，但未标记该注入问题。Wiz 后续澄清：Copilot 是该 PR 的共同作者并给出「无问题」结论，但尚不清楚代码变更本身是否由 AI 协助生成。
  • PoC 获取到的 Jira 令牌可读取 Snowflake 的部分内部项目。Snowflake 当天恢复安全的 env: 与 jq --arg 解析模式、随后轮换令牌；审计日志确认没有第三方未经授权访问。

为什么重要

这起事件的关键不是把漏洞简单归因于 AI，而是说明 AI 参与的开发与审查流程仍可能遗漏传统的 shell 注入风险；与此同时，自动化安全智能体可将漏洞发现窗口压缩到数天甚至更短。团队需要对 CI/CD 中的不可信输入、工作流权限和密钥暴露实施可执行的防护规则，并缩短修复与凭据轮换周期。

关键要点

  • 不可信事件字段不能直接插入 shell run: 语句。
  • 自动化扫描与 AI 审查不能替代针对工作流的安全审计。
  • 报道称 Snowflake 已当天修复并完成事后核查。
