微软推出 Scout：基于 OpenClaw 框架的个人 AI 助手，深度集成 Microsoft 365

原文要点

微软在 Build 2026 期间正式推出 Scout，一款基于 OpenClaw 框架构建的持久型个人 AI 助手，专为 Microsoft 365 生态系统设计：

  • 持久身份与持续学习：用户为 Scout 命名（如演示中的"Sebastian"），Scout 会根据用户反馈不断调整其行为模式，形成针对个人的"记忆和技能"，随使用时间推移变得更加精准和自主。
  • 跨平台操作：Scout 基于云端运行，覆盖桌面和 Web 浏览器，可连接邮件、日历和其他 Microsoft 365 系统。
  • 内置技能 + 用户自定义：提供日程管理和会议议程起草等预制技能，但核心价值在于用户自定义的技能开发——用户可以根据自己的工作习惯构建专属自动化能力。
  • 定价与获取方式：通过微软 Frontier 计划（面向早期采用者的实验性产品计划）开放，需要 GitHub Copilot 订阅才能使用。
  • OpenClaw 渊源：Scout 直接基于 OpenClaw 框架开发，OpenClaw 曾在 2026 年初引发 AI 圈广泛讨论（因一位 Meta AI 安全研究员的 AI 代理失控事件），但其"持久型代理"理念已被微软采纳并产品化。

为什么重要

Scout 的推出代表了一个重要趋势：个人 AI 助手正在从"问答工具"进化为"个人工作代理"。这一转变有几个深层含义：

  1. 微软选择了 OpenClaw 生态，而非从头构建。这说明 OpenClaw 的代理框架（持久身份、技能系统、记忆机制）已经证明了其技术路径的可行性，并获得了企业级生态的认可。这对 OpenClaw 生态的长期发展是一个重大背书。

  2. "用户教育"将成为 AI 个人助手成功的关键变量。Scout 的最大价值在于用户自定义技能，但大多数用户并不知道如何设计一个有效的 AI 技能。这与 Salesforce 的 Agentforce 平台战略不同——Salesforce 提供开箱即用的 50+ 领域代理；微软的路径更依赖用户自建，对用户的 AI 素养要求更高。

  3. Frontier 计划的定位值得关注。Scout 需要 GitHub Copilot 订阅，这说明微软正在将实验性 AI 产品与开发者工具捆绑，以开发者生态作为 AI 助手扩散的主要渠道。这是微软一贯的"平台+生态"策略在 AI 时代的延续。

  4. 记忆和技能的持久化是差异化核心。当用户花时间训练 Scout 理解自己的工作习惯后，切换成本将急剧上升——这与 GitHub Copilot 随着使用变得更好用但用户难以迁移的逻辑相同。微软正在用"使用即锁定"的策略构建用户粘性。

关键要点

  • Scout 是微软首个基于 OpenClaw 框架的持久型个人 AI 助手，拥有持续学习和记忆能力
  • 通过 Microsoft 365 生态系统（邮件、日历、Web）实现跨平台操作
  • 需要 GitHub Copilot 订阅，并通过 Frontier 早期采用者计划开放
  • 微软押注用户自定义技能是核心价值，但同时设置了较高的 AI 素养门槛
  • OpenClaw 框架获得微软企业级认可，持久型代理的技术路径已被市场验证
