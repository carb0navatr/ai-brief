Google Cloud COO：AI 安全必须进入董事会，而非停留在机房

为什么重要

AI 安全正在从"技术问题"升级为"治理问题"。Google Cloud COO Francis deSouza 的表态代表了大厂对 AI 安全定位的根本性转变：当攻击时间窗口从 8 小时压缩到 22 秒、企业 AI 资产扩展到模型、数据管道、Agent 和 Prompt，安全的责任主体已无法继续外包给 IT 部门。这对 AI Agent 的企业采纳和安全合规框架有直接影响。

关键要点

  1. 平台安全从第一天抓起：deSouza 明确表示"没有 AI 战略就没有数据战略和安全战略，三者必须并行"，并强调"安全不能事后添加，也不能指望员工自行搞定"。这是对"先上线再打补丁"模式的直接否定。

  2. 影子 AI 的风险：员工绕过公司审批使用消费者级 AI 工具，形成组织内的安全盲区。deSouza 警告 AI Agent 可能挖掘出被遗忘的数据源（如深埋的旧 SharePoint 服务器），扩大攻击面。

  3. 攻击时间窗口从 8 小时压缩至 22 秒：企业遭受初始入侵到攻击者完成横向移动的时间大幅缩短，要求安全响应速度同步提升。

  4. Agent 级防御："不再需要人工主导防御，甚至不需要人在回路中，而是人类监督完全自主的 Agent 防御"，这是 deSouza 提出的安全架构演进方向。

  5. 多云现实：即使企业认为自己只用了一家云服务商， SaaS 应用和业务合作伙伴几乎必然会引入多云环境，安全策略必须跨云统一。

  6. Google 自身也存在短板：安全公司 Aikido 发现 Google API Key 的撤销传播存在约 23 分钟的窗口期，期间攻击者仍可使用被盗密钥；新版凭证格式（AQ 前缀）已可在约 1 分钟内撤销，说明问题并非技术不可解，而是优先级问题。
