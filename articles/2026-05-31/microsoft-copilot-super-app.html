Microsoft Copilot Super App：整合编程、聊天与 Agent 工作流的超级入口

来源：全文 | 原文

原文要点

据 Fortune 独家报道，微软正在打造一款整合其全线 Copilot 产品的"超级应用"，目标是将 GitHub Copilot（编程辅助）、Copilot Chat（对话助手）、Copilot Cowork（协作工具）以及一个内部代号为"Autopilot"的新 Agent 工作流功能，统一入口体验。

这一项目由微软新任 Copilot 负责人 Jacob Andreou 主导，其核心使命是将 Copilot 的消费者版与企业版整合为统一产品。内部口号为"Delivering one Copilot"。预计将在本周的 Microsoft Build 开发者大会上有所暗示，正式发布时间定在夏末。

现有 Copilot 产品线分散在不同产品中：Microsoft 365 的4.5 亿付费用户已可使用部分 Copilot 功能，GitHub Copilot Pro 版每月 $10 起，有超过 470 万付费订阅者。但面临来自 Cursor 和 Anthropic Claude Code 的激烈竞争，消费者版 Copilot 在活跃用户数上也落后于 OpenAI 和 Google 的聊天机器人。

为什么重要

微软 Copilot 产品线长期存在分散问题——不同产品各自为政，用户体验碎片化。这款超级应用标志着微软 AI 战略从"功能点状嵌入"转向"平台级整合"，是 Nadella 领导下的一次重大产品架构调整。

更深层的背景是微软股价承压、Nadella 正在重组高管团队，这次整合既是产品层面的优化，也是管理层对 AI竞争力下滑的应对之举。如果超级应用成功，它将成为微软 AI能力的统一入口，直接对标 OpenAI 的 Agent生态。

关键要点

  1. 超级应用整合四大 Copilot 模块：GitHub Copilot、Copilot Chat、Cowork 和代号 Autopilot 的 Agent 工作流，统一入口体验
  2. Jacob Andreou 主导整合战略，核心目标是将消费者版与企业版 Copilot 融合为统一产品
  3. 内部口号"Delivering one Copilot"，反映了微软对产品碎片化问题的明确认知
  4. 竞争压力驱动整合：GitHub Copilot 面临 Cursor 和 Claude Code 竞争，消费者 Copilot 落后于 OpenAI/Google
  5. 预计夏末发布，Build 大会将有所暗示——这是微软 AI 战略转向平台级整合的关键信号
