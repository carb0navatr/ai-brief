arXiv 新论文：「幽灵工具调用」——解决推测性 Agent 工具的时机隐私问题

2026 年 6 月 1 日发表于 arXiv 的论文「Ghost Tool Calls: Issue-Time Privacy for Speculative Agent Tools」提出了一种新技术机制，旨在解决 AI Agent 在用户确认前发出推测性工具调用时可能泄露用户意图或敏感数据的隐私风险。该问题在金融、医疗、法律等受监管行业尤为突出，直接影响 GDPR 和 EU AI Act 下的隐私设计义务。

关键要点

  • 幽灵工具调用机制：允许 AI Agent 发出工具请求，但不向用户或系统透露具体工具或其参数，直至该调用实际执行，从而防止推测性工具调用提前泄露敏感信息。

  • 适用场景：部署高级 AI Agent 的组织，特别是在金融、医疗、法律等受监管行业，以及使用推测性或自主性 AI Agent 与外部数据库、API 或用户数据交互的系统。

  • 合规影响：在 GDPR 和 EU AI Act 框架下，「隐私设计」义务要求评估此隐私风险，相关团队应更新风险评估和文档。

  • 建议行动：合规团队应立即审查 AI Agent 架构；评估引入「幽灵工具调用」技术与隐私设计义务的契合度；与监管机构沟通以澄清 Agent 透明度和用户同意的预期。

从模型 Scaling 到系统 Scaling：AI Agent 框架（Harness）的六大组件

加州大学伯克利分校 Shangding Gu 的论文「Scaling the Harness in Agentic AI: System Design Beyond Model Scaling」（arXiv:2605.26112）提出：当基础模型足够强大后，长期运行 AI Agent 的性能瓶颈已不再是模型本身，而是模型周围的执行框架（harness）。论文系统拆解了 orchestrator、memory、context constructor、skill router、verification/governance 六大组件，为 Agent 系统的可复现工程研究提供了方法论框架。

关键要点

  • 模型分数 ≠ 模型+框架分数：SWE-bench 测试证明，固定基础模型仅通过改进 Agent-Computer Interface 即可大幅提升性能；τ-bench 显示单次测试表现良好的 Agent 在重复运行中可能崩溃（pass@k 指标）。

  • 框架六组件：R（推理基座模型）、M（Memory 存储）、C（Context 构造器）、S（Skill 路由器）、O（编排循环）、G（验证与治理）。

  • 三大系统瓶颈：Context governance（暴露但无访问权）、Trustworthy memory（过时但自信）、Skill routing（自信但未校验），各有对应的系统修复策略。

  • Benchmark 建议：框架级评估应同时报告结果指标和过程指标（轨迹质量、记忆卫生、上下文效率、通信保真度、验证成本），而非仅依赖单次通过率。

  • 开源参考实现：CheetahClaws（GitHub: SafeRL-Lab/cheetahclaws）将框架变量显式化，便于实验和复现。
